# 部署方式对比

| 部署方式 | 适用场景 | 费用 | 启动时间 | 扩展性 |
|---------|---------|------|---------|--------|
| **本地开发** | 开发调试 | 免费 | 秒级 | 单实例 |
| **Docker** | 自托管/企业内网 | 服务器成本 | 秒级 | 手动扩展 |
| **Vercel** | 公网快速部署 | 免费层/Pro | 冷启动 1-3s | 自动扩展 |

## 1. 本地开发

**优点：**
- 即时反馈（hot reload）
- 完全控制
- 无网络延迟

**缺点：**
- 仅限本机访问
- 需要自行安装 Python 环境

## 2. Docker 部署

**优点：**
- 环境一致性（容器化）
- 适合自托管、企业内网
- 可与 k8s/docker-compose 集成

**缺点：**
- 需要维护服务器
- 需要手动配置负载均衡/自动扩容

## 3. Vercel 无服务器部署

**优点：**
- 零运维（无需维护服务器）
- 自动 HTTPS、CDN、全球加速
- 自动扩展（无限并发）
- GitHub 集成（Push 即部署）
- 免费额度（个人/小项目足够）

**缺点：**
- 冷启动延迟（1-3秒）
- 函数执行时间限制（Hobby: 10s, Pro: 60s）
- 只读文件系统（不能写本地文件）
- 依赖包体积限制（250MB）

## 选择建议

### 选择本地开发
- 开发调试阶段
- 需要频繁修改代码

### 选择 Docker
- 企业内网部署
- 需要自托管
- 对延迟敏感（无冷启动）
- 需要持久化存储

### 选择 Vercel
- 个人项目/演示
- 希望快速上线
- 流量不确定（自动扩展）
- 不想维护服务器
- 需要全球 CDN
